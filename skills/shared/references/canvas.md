# Canvas — 固定尺寸产物

默认情况下图有多大由内容决定。当产物要发到一个**尺寸固定的位置**（小红书封面、
幻灯片、公众号头图、A4 打印）时，需要给 `render_diagram` 传 `canvas`。

但**画布是结果，不是前提**。除非用户直接点名了尺寸，否则不要一上来就挑比例 ——
先让内容决定布局，再由布局量出比例，最后才落到画布。整条链见 §2。

---

## 1. 什么时候需要 canvas

需要 —— 用户提到了投放位置或尺寸：

- "画个小红书封面" / "发小红书的图" / "发朋友圈"
- "做成 3:4" / "竖版" / "4:3" / "1:1"
- "放进 PPT" / "幻灯片" / "16:9"
- "打印出来" / "A4"
- 直接给了像素："1242×1656"

不需要 —— 图只是贴进 Markdown / Notion / 聊天窗口。这些地方会自适应，
固定尺寸只会平白多出留白。**不确定时不要加 canvas**，内容自适应是更好的默认。

---

## 2. 决策链：内容 → 布局 → 比例 → 画布

先分清用户给到哪一步：

- **点名了比例**（"做个 3:4 的封面"）→ 画布已定，跳到 §3 直接按它排版。
- **只说了平台**（"发小红书"）→ 比例要你来定，走下面三步。

### 第一步：内容决定布局

判据是横轴承载什么。注意这里有**两种不同的重排**，不要混为一谈：

- **折行（wrap）** —— 把第 4 项挪到第二行开头。会打乱顺序，横轴有语义时禁止。
- **转轴（transpose）** —— 整条轴从横向改成纵向。顺序完全保留，通常是合法的。

| 横轴承载 | 图类型 | 折行 | 转轴 | 竖画布下的做法 |
|---|---|---|---|---|
| **顺序** | 时间线 / roadmap、泳道图 | ❌ | ✅ | **转成纵向**：时间/流程从上往下走，卡片变宽变矮 |
| **连续刻度** | 甘特图 | ❌ | ❌ | 只能横版；太长就按时间段拆成多张 |
| **并列主体** | 时序图（横轴是 actor，时间本来就朝下） | ❌ | ❌ | 天然就竖，actor ≤ 5 时直接用 3:4 |
| **无语义** | 流程图、架构图、节点集合、卡片列表、四象限 | ✅ | ✅ | 排成接近正方形 |

**竖版时间线是标准做法，不是妥协。** 五个里程碑横排是 3.2:1（`UNDERFILL`，fill 22%），
转成纵向后是 0.74:1（fill 98%，零告警）—— 同样的内容和顺序，只是换了个方向。
遇到竖画布先想转轴，不要急着拆图。

转轴不是把宽高对调：横版卡片窄而高（240×180），竖版卡片宽而矮（890×180），
文字从两三个字一行变成整句一行，可读性反而更好。

横轴无语义的图要排成方形，不是为了迁就画布，是排版通识：**方形排布扫视路径最短、
信息密度最高**。6 个节点横着拉成 6:1，读者要从左扫到右；排成 2×3，一眼看全。

```text
compute_layout({ helper: "chooseGrid", args: {
  count: 6, targetAspect: 1, cellW: 300, cellH: 120, colGap: 40, rowGap: 60
}})
→ { cols: 2, rows: 3, w: 640, h: 480, aspect: 1.33 }
```

### 第二步：量出自然比例 → 选画布

拿第一步布局的 `aspect`（宽/高，记作 r），选最接近的画布：

| r | 小红书 | 通用 |
|---|---|---|
| < 0.87 | `xhs:cover` (3:4 = 0.75) | 竖版 |
| 0.87 – 1.15 | `xhs:square` (1:1) | 方图 |
| 1.15 – 2.4 | `xhs:landscape` (4:3 = 1.33) | 横版 |
| > 2.4 | 都不行 → 第三步 | — |

分界不是拍的，但前三档和最后一档来源不同：

- **0.87 / 1.15 是"选最接近"的分界** —— 相邻两个画布比例的几何平均
  (√(0.75×1) = 0.87，√(1×1.33) = 1.15)。`fill` 是比值，所以在对数尺度上取中点，
  两边才对称。
- **2.4 是"还装得下"的上限** —— `fill = 内容比例 ÷ 画布比例`（小的除大的），
  `CANVAS_UNDERFILL` 门槛 0.55 即 1.8 倍失配，4:3 × 1.8 = 2.4。超过它连最横的
  画布都会告警。

顺带记住另外两个上限，用来判断"降级到底行不行"：3:4 撑到 r ≤ 1.36，1:1 撑到
r ≤ 1.8。

**平手时（r 卡在两档边界，两个画布都成立）小红书选更竖的那个** —— 信息流是竖向
瀑布流，3:4 的占位高度比 1:1 高 33%、比 4:3 高 78%，曝光更大。曝光只在这里当
裁决规则，不当默认值。

顺带一个常见结果：可重排的图排成方形后 r 通常落在 0.8–1.5，而 3:4 = 0.75 离方形
只差 1.33 倍，远在门槛内 —— 所以**流程图/架构图发小红书用 3:4 几乎总是成立的**。

### 第三步：r > 2.4，先回头看能不能转轴

三个画布都会 `CANVAS_UNDERFILL`。按优先级处理，**前两条都是改布局，不是改内容**：

1. **转轴** —— 回第一步查表。时间线、泳道、以及所有横轴无语义的图都能转竖，
   转完 r 通常直接落进 3:4 区间。**最常被跳过的一步，先试这个。**
2. **折行** —— 横轴无语义时用 `chooseGrid` + `serpentine`（见 §3）。
3. **拆成多张** —— 转轴折行都不适用（甘特、超长时序）时。小红书是多图笔记
   （最多 18 张），8 节点时间线拆成 2 张 4 节点的 3:4，比 1 张糊掉的 4:3 强。
4. **减节点** —— 一张图 4–6 个节点是上限，封面尤其。
5. **留白填文案** —— `xhs:landscape` + `align: "bottom"` 把图压下去，顶部空白
   放标题。
6. 实在不行才接受 4:3 + 小字。

## 3. 选定画布后：按它重排

画布定了以后再用**画布的比例**重排一次，把 fill 拉满。第一步排方形是为了
判断方向，这一步是为了填满。

```text
targetAspect = canvas.width / canvas.height    // xhs:cover → 0.75

compute_layout({ helper: "chooseGrid", args: {
  count: 6, targetAspect: "3:4", cellW: 300, cellH: 120, colGap: 40, rowGap: 60
}})
→ { cols: 2, rows: 3 }

compute_layout({ helper: "gridLayout", args: {
  count: 6, cols: 2, cellW: 300, cellH: 120, colGap: 40, rowGap: 60, serpentine: true
}})
```

链式流程一定要加 `serpentine: true`：折行后第 3 步和第 4 步仍然相邻（蛇形走位），
箭头不用横跨整幅图。`gridLayout` 也可以省掉 `cols` 直接传 `targetAspect`。

### 竖版（3:4 / 4:5）的手法

- 主流程方向从上往下，不是从左往右
- 一行放不下就折行，不是缩小
- 层级 / 分组图：层数多、每层窄
- 字号往上调一档 —— 封面在手机上看，比文档里的图要大

### 极扁画布（公众号头图 2.35:1）

只放得下一条主线 + 标题。多层结构不要往这里塞，换 `wechat:share` 方图。

## 4. canvas 相关的 warnings

和其它 lint 一样：**有 warning 就是没做完**，改了重画。

| code | 含义 | 怎么改 |
|---|---|---|
| `CANVAS_UNDERFILL` | 内容比例和画布差太远，缩放后只占一小块 | 按 §3 重排；重排后仍然超标说明选错了画布，回 §2 第二步重选，或走第三步拆图 |
| `TEXT_TOO_SMALL` | 缩放后字太小，成品上看不清 | 调大 `fontSize`、砍内容，或重排以减少缩放 |
| `CANVAS_OVERFLOW` | 内容超出画布（只在 `fit:"none"` 下出现） | 用默认 `fit:"contain"`，或缩小布局 |

`CANVAS_UNDERFILL` 是**重排信号**，不是留白信号 —— 它的意思是"你为错误的形状排了版"。
调 padding 没用。

渲染结果里的 `canvas: { width, height, scale, fill }` 可以自查：`fill` 是内容占
可用区域的比例，`scale` < 1 说明内容被压缩过。**决策不用猜，渲一次看 `fill` 就知道。**

## 5. preset 查表

`canvas: { preset: "<id>" }`。完整 id 列表见 `render_diagram` 工具描述
（或 CLI `excalidrawer presets`）。比例是选型依据 —— 先按 §2 定比例，再来查 id：

| 场景 | preset | 比例 |
|---|---|---|
| 小红书封面 / 竖版 | `xhs:cover` | 3:4 |
| 小红书方图 | `xhs:square` | 1:1 |
| 小红书横图 | `xhs:landscape` | 4:3 |
| 公众号头图 / 文章封面 | `wechat:article-cover` | 2.35:1 |
| 微信分享缩略图 | `wechat:share` | 1:1 |
| 抖音封面 | `douyin:cover` | 3:4 |
| B站视频封面 | `bilibili:cover` | 16:10 |
| 推特 / X 配图 | `x:card` | 16:9 |
| LinkedIn 配图 | `linkedin:post` | 1.91:1 |
| Instagram | `instagram:portrait` | 4:5 |
| PPT / 幻灯片 | `slide:16-9` | 16:9 |
| 打印 / A4 | `a4:portrait` / `a4:landscape` | — |

没有对应 preset 时直接给几何：

```jsonc
canvas: { width: 1242, height: 1656 }      // 显式像素
canvas: { ratio: "3:4", width: 1242 }      // 比例 + 一条边
canvas: { ratio: "16:9", height: 1080 }
```

**preset 里的像素只是一个足够高的输出分辨率，真正重要的是比例。** 平台会自己缩放；
用户明确要求某个像素尺寸时，用显式 `width`/`height` 覆盖。

1:1 除了作为降级选项，这两种情况是主动最优解：内容天然方（四象限、2×2 矩阵、
hub-and-spoke 辐射图、单结论卡），或者要跨平台复用（1:1 在微信 / Instagram / X
都能直接用，3:4 出了小红书就得重做）。

## 6. 其它 canvas 选项

```jsonc
canvas: {
  preset: "xhs:cover",
  padding: 80,                 // 画布内边距，默认短边的 6%
  safe: { bottom: 220 },       // 平台 UI 遮挡区，内容会自动避开
  fit: "contain",              // 默认；"pad" 只缩不放，"none" 保持 1:1
  align: "center",             // 或 top / bottom / left / right / top-left ...
  background: "#ffffff",       // 或 "transparent"
}
```

- `safe` 是**避让区**，不是警告区：它会缩小可用区域，内容自动排在外面。
  preset 自带的 safe 目前都未实测，所以不会生效 —— 需要时自己传。
- **`.excalidraw` 永远保存原始坐标**，不受 canvas 影响，用户打开还能正常编辑。
  canvas 只作用于 SVG / PNG。
- 带 canvas 时 `scale` 默认 1（像素已经精确），不需要再传；只有要超采样时才传。
