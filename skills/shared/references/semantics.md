# 视觉语义：意思 → 组件 + 参数

[`sugar.md`](sugar.md) 回答"有哪些组件、参数怎么写"；本文件回答"**这个意思该选哪个组件、传什么参数**"。
输入是用户的自然语言和上下文（"A 异步通知 B"、"这一步是可选的"），输出是组件选择和样式参数。

各图表 recipe 只写**和这里不同**的约定（比如 sequence 把"虚线"收窄成"响应"），其余一律按本文件。

## 0. 优先级与总原则

**优先级（高 → 低）：** 用户明确要求 → recipe 的特殊约定 → 本文件的通用规则 → 组件默认值。

四条总原则，每张图都适用：

1. **一种样式只表达一种意思。** 同一张图里虚线一旦表示"异步"，就不能再拿来表示"可选"。需要两种意思时换一个维度（线型 vs 颜色 vs 粗细），不要复用。
2. **样式不用来装饰。** 没有含义要表达就用默认值：实线、默认粗细、`arrow` 箭头。默认值本身就是"普通关系"的意思。
3. **含义不明显时加图例**（§8）。实线/虚线区分请求/响应这类通用约定不需要；自定义含义（"虚线 = 计划中的服务"）需要。
4. **拿不准就问。** 用户描述里分不清（哪些调用是异步的？哪些模块是计划中的？），在 clarify 环节用 AskUserQuestion 问，不要自己猜。猜错的虚线比没有虚线更误导。

## 1. 选组件：有没有方向

| 意思 | 组件 | 写法 |
|---|---|---|
| 有方向：调用、流转、发送、依赖、因果、"→ 下一步" | `arrow` | `{ shape: "arrow", ... }` |
| 双向：同步、互相调用、双向数据流 | `arrow` 两端箭头 | `startHead: "arrow"` + 默认 `head` |
| 没有方向：结构、归属、层级、连接、边界 | `line` | `{ shape: "line", ... }` |

`line` 的典型场景：sequence 生命线、timeline 轴线（除最后一段）、tree 的父子连接、分隔线、把注释连到目标的引线。

**不要用 `arrow` + `head: "none"` 代替 `line`。** 两者画出来一样，但 `.excalidraw` 里元素类型不同，用户在 Excalidraw 里编辑时看到的属性面板也不同；而且同一件事两种写法，模型容易混。旧写法仍能渲染，只是不再使用。

树、层级图的方向已经由根的位置表达了，连接线默认用 `line`；只有边真的表示"流向"时才用 `arrow`。

## 2. 线型 `strokeStyle`：确定性与强弱

| 线型 | 意思 | 例子 |
|---|---|---|
| `solid`（默认） | 确定、同步、必然发生、已存在 | 请求、函数调用、主流程的下一步、已上线的服务 |
| `dashed` | 异步、返回、可选、计划中、弱依赖 | 响应/返回值、消息队列/事件、可选步骤、TODO/规划中、软依赖 |
| `dotted` | 推断、注释、边界、"大致如此" | 注释引线、推测的关系、信任边界、范围框 |

`dashed` 列了五种意思——按原则 1，**一张图里只选其中一种**。最常见的冲突是"返回"和"异步"同时出现：返回用 `dashed`，异步改用颜色（如 `stroke: "purple"`）或在 label 里写明 `async`。

形状也适用同样的含义：`dashed: true` 的框 = 分组容器、计划中的模块、可选组件（形状 sugar 只有 `dashed`，没有 `dotted`）。

## 3. 粗细 `strokeWidth`：主次

| 粗细 | 意思 |
|---|---|
| `thin`（1） | 辅助、背景、次要连线：生命线、网格、注释引线 |
| `medium`（2，默认） | 普通关系——绝大多数连线 |
| `bold`（4） | 主路径、关键路径、用户要求强调的那一条 |

`bold` 是稀缺资源：一张图里超过 1/3 的线是粗的，就等于没有强调。没有明确的"主路径"就全部用默认。

## 4. 端点 `head` / `startHead`：关系类型

| 端点 | 意思 |
|---|---|
| `arrow`（默认） | 普通指向——绝大多数情况 |
| `triangle` / `triangle_outline` | UML 继承/实现（空心）、强调的数据流（实心）。只在用户的领域本来就用这套记号时使用 |
| `diamond` / `diamond_outline` | UML 组合（实心）/ 聚合（空心） |
| `circle` / `circle_outline` | 起点标记、连接点、"可选"端（ER 风格） |
| `bar` | 终止、边界、"到此为止" |

除 `arrow` 外的端点都是**记号**，读者需要认识这套记号才看得懂。用户没有用 UML / ER 的语境，就只用 `arrow`。

## 5. 路径形态 `arrowType` / `edges`：整齐还是松散

| 形态 | 用在 |
|---|---|
| `elbow` | 方框之间按 `from`/`to` 自动布线的连线——flowchart、architecture、comparison。横平竖直，拐角圆滑 |
| `round`（代码默认） | 自由曲线：手画感的注释、mind map 式的松散关系、绕开障碍的手动路径（L4 `points`） |
| `sharp` | 需要硬拐角的折线：时间轴、坐标、几何示意 |

`line` 只有 `edges: "sharp"`（默认）/ `"round"`：结构线（生命线、轴线、树连接）用 `sharp`；装饰性的曲线用 `round`。

为什么自动布线要显式写 `elbow`：自动布线产生的是横竖折线（直线 / L 形 / Z 形 / U 形），代码默认的 `round` 会把这些折点平滑成 S 形曲线，拐弯处像蛇一样扭。`elbow` 保留折线的整齐。

## 6. 颜色

7 色 palette，全部为手绘风浅色填充：

| 关键字 | 意思 |
|---|---|
| `yellow` | 起点 / 主体对象 / 用户侧 |
| `blue` | 主线流程 / 服务层 / "我们这边" |
| `green` | 成功 / 终态 / 数据存储 |
| `purple` | 外部依赖 / 第三方 |
| `red` | 错误 / 异常 / 警示——只用于真正的坏情况 |
| `orange` | 判断节点 / 决策点 / 中间状态 |
| `gray` | 基础设施 / 辅助元素 / 中立方 |

每个关键字还有两个变体：`bgXxx`（更浅的底色，用于分组容器）和 `stroke` 色（`stroke: "blue"` 自动解析为对应的深色描边）。

- **同色聚类**：同一语义层用同一颜色（architecture 一整层都是 `blue`；tree 一整个分支一个色系）。
- **决策节点用 `orange`/`yellow`，终态用 `green`。**
- **`red` 不做强调色。** 红色读作"出错了"，拿来高亮正常节点会误导。要强调用 `bold` 或 `blue`。
- **一张图不超过 4 种颜色。** 超过会显得花。
- **连线默认墨色。** 连线上色只在颜色承载含义时（按服务着色、区分异步调用）才用，否则会和节点颜色抢。

**默认颜色循环**（不指定时）：`yellow → blue → green → purple → red → orange`，跳过 `gray`（只在显式指定时用）。timeline 的 items、sequence 的 actors、architecture 的 sections 默认按这个顺序上色。

**模板 CLI**（`excalidrawer generate`）的节点级 `color` 字段同样接受这些关键字，也接受 `#rrggbb`，但十六进制会失去 palette 一致性，一般用关键字。

## 7. 从描述到参数：速查

| 用户这么说 | 组件 + 参数 |
|---|---|
| "A 调用 B"、"A 请求 B"、"然后"、"→" | `arrow`（全默认） |
| "返回"、"响应"、"回调结果" | `arrow` + `strokeStyle: "dashed"` |
| "异步"、"发消息到队列"、"触发事件"、"通知" | `arrow` + `strokeStyle: "dashed"`（若图里虚线已表示"返回"，改用颜色区分，见 §2） |
| "可选"、"必要时"、"可跳过" | `arrow` + `strokeStyle: "dashed"`；可选的**节点**用 `dashed: true` 的框 |
| "计划中"、"TODO"、"二期"、"未上线" | 框和连线都 `dashed`，并加图例 |
| "双向"、"互相"、"同步数据" | `arrow` + `startHead: "arrow"` |
| "属于"、"包含"、"下级"、"分为" | `line`（tree / 层级） |
| "主流程"、"关键路径"、"重点" | `strokeWidth: "bold"`，其余默认 |
| "大概"、"推测"、"可能有关" | `strokeStyle: "dotted"` |
| "继承"、"实现"（UML 语境） | `arrow` + `head: "triangle_outline"` |
| "失败"、"报错"、"异常分支" | 目标节点 `fill: "red"`，连线保持默认 |

例：用户说"订单服务下单后**异步**发消息给库存服务，库存服务**返回**扣减结果"。这张图里同时有"异步"和"返回"——按原则 1，虚线只能给其中一个。sequence 图的惯例是虚线 = 返回，所以：

```js
{ shape: "arrow", from: "order", to: "mq",  text: "OrderCreated (async)", stroke: "purple" },
{ shape: "arrow", from: "stock", to: "order", text: "deduct result", strokeStyle: "dashed" },
```

## 8. 图例

用了自定义含义（不是请求/响应这类通用约定）时，在图的右下角或标题下方加图例：每行一个短样本线 + 一个 `text`。

```js
{ shape: "line", at: [x, y + 10], points: [[0, 0], [40, 0]], strokeStyle: "dashed" },
{ shape: "text", at: [x + 50, y], size: [140, 20], text: "planned (Q3)", fontSize: 14 },
```

图例 ≤ 3 行。需要更多行，说明这张图承载了太多种含义，先考虑拆图。
