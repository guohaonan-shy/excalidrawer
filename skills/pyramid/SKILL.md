# excalidrawer pyramid

金字塔和漏斗是同一种图的两个方向：一摞逐层收窄的梯形，每层一个名字。金字塔下宽上窄，讲层级和依赖，底层支撑上层（需求层次、测试金字塔、数据分层）；漏斗上宽下窄，讲逐步流失，每层带一个数（注册转化、销售管线、招聘流程）。读者应该一眼看出有哪几层、谁在上谁在下；漏斗还要让人看出在哪一步流失最多。下面四步走：问清楚、构图、出图、对照常见画坏法检查。

## 1. 问清楚

用户的描述已经能列全这张图的全部内容（每一层是什么；漏斗还有每层的数）就不问，也不去读提问规则。金字塔还是漏斗、漏斗显示什么，是怎么画的选择，先看内容能不能推出来，推不出来、用户没说的再问。否则先看提问的通用规则：调 skill `steps`（Claude Code 用 Skill 工具调 `excalidrawer:steps`；其他宿主读 `../steps/SKILL.md`），看它的『clarify』。这一步只读这一节。

要问的事：

1. **每层是什么**：自由文本。金字塔列出每一层的名字，注明从上到下还是从下到上（需求层次常从最底层说起）；漏斗列出每一步的名字和数。用户给的是一张表、一段数据或一份报告里的几行时，直接从里面读，不再问。
2. **金字塔还是漏斗**：按用户给的东西判断，不先问。给了逐层递减的数（访问 10000、注册 4200、付费 360），就是漏斗；只给层级、依赖、"谁支撑谁"，就是金字塔；两样都不像（比如只列了几项，没说有没有先后、有没有数）才问，单选，推荐项放第一位：
   - 金字塔（推荐，没有数、只有层级）。
   - 漏斗（每层有数，要看流失）。
3. **漏斗显示什么**：只有漏斗问，用户没说就问。单选，推荐项放第一位：
   - 绝对数和转化率都显示（推荐）：每层右边写数，两层之间写转化率。
   - 只显示绝对数。
   - 只显示转化率：每层右边不写数，只在层间写转化率；用户只给了转化率没给绝对数时直接用这个，不问。

导出格式不用先问：对话里读得出图要去哪就直接定，读不出来才在出图时问一句（规则在 `steps` 的『出图』里）。

## 2. 构图

组件的用法：调 skill `steps`（Claude Code 用 Skill 工具调 `excalidrawer:steps`；其他宿主读 `../steps/SKILL.md`），看它的『组件』。这一步只读这一节，再读下面用到的那几份参考：taper（梯形层的坐标）、形状与文字（梯形用的多边形，和层名、数值这些文字）、semantics（颜色和标题）。

### 一张好的金字塔 / 漏斗长什么样

两种图都是左右对称的一摞梯形，层与层之间留一道缝，缝让每层各是各的，斜边连起来又是一条直线。层名压在梯形正中。

```text
      金字塔                              漏斗

        ______                    __________________   10,000
       /  顶层 \   备注            \    访问网站     /
       ‾‾‾‾‾‾‾‾                    ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾     42%
      ____________                 \   开始注册   /    4,200
     /    中层    \  备注           ‾‾‾‾‾‾‾‾‾‾‾‾
     ‾‾‾‾‾‾‾‾‾‾‾‾‾‾                      …
    ________________
   /      底层      \  备注
   ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
```

- **金字塔**：层按自上而下排，塔尖是第一层。用户按"底层在前"说的，先反过来再排。每层右边可以写一句短备注（灰字），没有就不写；塔尖那一层最窄，名字要短。
- **漏斗**：入口是第一层，最宽。**层宽只跟层序有关，不跟数值成比例**：按数值缩放时，转化率低的最后一两层会窄到放不下字，所以数值写在层的右边，不靠宽度表达。每层右边写这一步的数；两层之间的缝里写转化率（下一层除以上一层），用灰色小字，并在副标题里写一句"灰字 = 相邻两步的转化率"。用户只要其中一样，就只写那一样。
- **层名折行**：层名放不下一行时会折行，这一层跟着长高，下面的层往下挪。层名太长就先缩短，比如"完成首次付费的用户"缩成"付费用户"；不要靠缩字号。
- **标题**：点明这张图讲什么，漏斗写出在看哪一段流失（"Signup funnel — where visitors drop off"），金字塔写出层级按什么排（"Test pyramid"）。标题的字号和位置按 semantics。

### 用到的组件，各画出什么效果

- **taper**：给它每层的名字（漏斗再带数）、朝向（金字塔上窄、漏斗下窄）、最宽一层的宽度，它返回每层梯形的四个角、层名能用的文字框、数值和转化率的位置。层的位置和高度一律取它返回的，不自己算；最窄那条边的宽度不够放层名时，加大这个宽度参数，比如层名平均超过十个字符时。
- **形状与文字**：每层梯形画成一个填了色的多边形，层名、数值、转化率各是一段文字。层名画在文字框的位置，数值和转化率画在返回的锚点上。
- **semantics**：标题、副标题、灰字的字号和颜色。

### 配色倾向

整座金字塔或整个漏斗用同一种颜色，蓝色；层多时也不要每层换一个。想强调的那一层才换：漏斗里成交、付费这一层用绿色；用户点名要看流失最多的那一步，就把紧跟着流失的那一层用橙色；金字塔里用户分了类别（基础设施、业务、体验）才按类别分色，不超过三种。不用红色，红色读作"出错"。数值用墨色，转化率和备注用灰色，让数值先被读到。

### 数量上的判断

- 金字塔 3–5 层最好读，超过六层就把相近的层并起来。
- 漏斗 3–6 层。只有两层时，一个数加一个转化率就能说清，不必画图，除非用户要图。
- 漏斗的数要么单位一致，要么在副标题里写明单位（"visitors per month"）；混着不同的单位，转化率就没有意义，回去问用户。

出图、命名、导出格式、两层质量关、迭代：调 skill `steps`（Claude Code 用 Skill 工具调 `excalidrawer:steps`；其他宿主读 `../steps/SKILL.md`），看它的『出图』。这一步只读这一节。金字塔和漏斗的文件名都用 pyramid-<name>，漏斗图也是这个前缀。

## 4. 常见画坏法

| 画坏了长什么样 | 为什么 | 回到哪一步改 |
|---|---|---|
| 漏斗最后一两层窄得放不下层名，字挤出梯形 | 按数值缩放了层宽，或最窄那条边留得太小 | 构图：taper，层宽只跟层序有关；层名长就加大最窄边的宽度，或缩短层名 |
| 金字塔上下颠倒：塔尖是用户说的最底层 | 用户按"底层在前"说，没有反过来再排 | 问清楚：核对层的顺序，taper 的层永远自上而下给 |
| 层与层贴在一起，没有缝，或者缝大得像各是各的 | 层高和层间的缝不是 taper 返回的，自己排了 | 构图：taper，坐标一律取它返回的 |
| 某一层比别的层高出一截，下面的层被挤得不齐 | 层名折成了几行，这一层长高了 | 这是正常的；嫌难看就缩短这一层的层名 |
| 数值贴着梯形斜边，或每层的数值左右参差 | 数值没画在返回的锚点上，按各自的斜边位置排了 | 构图：taper，数值和转化率都画在它给的锚点上，同一列 |
| 转化率不知道是哪两层之间的，或读成了某一层的数 | 灰字没落在两层之间的缝里，也没有说明 | 构图：转化率用返回的位置，副标题写明灰字的意思 |
| 每层一个颜色，花成一片 | 没按"一座塔一种颜色，强调的才换"配色 | 构图：配色倾向 |
| 梯形没有颜色，只有轮廓 | 用线条拼的梯形，不是多边形 | 构图：形状与文字，梯形用多边形 |
| 出图后质量关有警告，或看图有一条不过 | 前面某一步的几何没改对 | 出图：按警告和自检的结论改，回到对应的构图那一项 |
