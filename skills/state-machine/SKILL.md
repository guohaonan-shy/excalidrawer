# excalidrawer state-machine

状态机讲一个东西在几个状态之间怎么跳：它现在可能处在哪些状态，什么事件、在什么条件下让它跳到哪个状态。读者应该一眼看出从哪进、最常走的那条路、在哪结束，以及哪些转移会回头。下面四步走：问清楚、构图、出图、对照常见画坏法检查。

## 1. 问清楚

用户的描述已经能列全这张图的全部内容（有哪些状态，以及每条转移从哪到哪、由什么事件触发）就不问，也不去读提问规则。主路径横排还是竖排是怎么画的选择，内容推不出来，用户没说的仍要问。否则先看提问的通用规则：调 skill `steps`（Claude Code 用 Skill 工具调 `excalidrawer:steps`；其他宿主读 `../steps/SKILL.md`），看它的『clarify』。这一步只读这一节。

要问的事：

1. **状态和转移**：自由文本。有哪些状态；每条转移从哪个状态到哪个状态、事件是什么，有没有条件（「仅管理员」「30 天内」）和动作（「发通知」）。用户给的是一段代码里的枚举加 switch、或一份状态表时，直接从里面读，不再问。
2. **初始和终止**：哪个是初始状态；有没有终止状态（订单完成、取消）。用户没提终止就不画终止，不硬凑。
3. **主路径的方向**：横排还是竖排。单选，推荐项放第一位：
   - 横排（推荐，状态名短、主路径五六个以内）：主路径从左到右一行，其余状态排在下面。
   - 竖排（状态名长、主路径超过六个）：主路径从上到下一列，其余状态排在右边。

可选的追问：有没有一个状态里还分子状态（「履约中」里分「打包」「已发货」）。

导出格式不用先问：对话里读得出图要去哪就直接定，读不出来才在出图时问一句（规则在 `steps` 的『出图』里）。

## 2. 构图

组件的用法：调 skill `steps`（Claude Code 用 Skill 工具调 `excalidrawer:steps`；其他宿主读 `../steps/SKILL.md`），看它的『组件』。这一步只读这一节，再读下面用到的那几份参考：形状与文字（初始点和终止双圈的画法在里面）、stack、连线、semantics；有复合状态时再读 panel，用了图例时再读 legend。

### 一张好的状态机长什么样

先挑出主路径：从初始状态到终止状态最常走的那一条，比如订单的「已创建 → 已支付 → 履约中 → 已送达」。主路径排成一行，读者顺着它读完就知道正常情况下发生什么。不在主路径上的状态（已取消、失败、挂起）另起一排，放在主路径下面，尽量放在跟它转移最多的那个状态正下方，这样两者之间的线是直的。

```text
 ●──▶[ Created ]──pay──▶[ Paid ]──▶┌ Fulfilling ──────────┐──▶[ Delivered ]──▶◉
       ↺ edit             │   ▲      │ [Packing]─▶[Shipped] │        │
                    cancel│   │restore└──────────────────────┘◀───────┘ return
                          ▼   │
                      [ Cancelled ]──▶◉
```

转移有五种，各有各的走法：

- **往前走**：主路径上相邻状态之间，直线。
- **回头**：回到前面状态的转移（退货、重新提交）从主路径不用的边走，绕到整排的上方或下方，不穿过中间的状态。
- **自环**：留在原状态的转移（编辑、重试、计时器触发），在状态框的一条空边上绕个小圈回来。
- **来回两条**：同一对状态之间方向相反的两条（取消 / 恢复），各占边的一侧，两条线分开、标签不叠。
- **离开主路径**：去下面那排的状态，从主路径状态的下边出去。

### 用到的组件，各画出什么效果

- **形状与文字**：每个状态是一个带文字的圆角矩形，名字用名词或形容词（Paid、Cancelled），不用动作。初始是一个实心的小黑点，一条箭头指向初始状态；终止是双圈：外圈空心、里面一个实心小圆。不在主路径上的终止状态（已取消）也接一个自己的双圈。
- **stack**：主路径是一排 stack，状态的宽度跟着名字走，同一排的状态一样高；初始点和终止双圈也是这一排里的格子，跟状态在同一条中线上。状态之间的间距要放得下转移的标签加上箭头头，按这一排的标签定，不按框定；只有一条标签特别长时，不让整排都跟着变宽，只撑开那一段，或者缩短那条标签。具体怎么留，看 connectors 参考里「相邻框之间放得下标签」。
- **连线**：所有转移都是横平竖直的直角折线，拐弯处是圆角。每条转移都钉住出入边，不交给自动选边：自环、来回两条、回头的转移各有写法，看 `steps` 的参考 connectors 里的「自环」「双向转移」「回边」「长距离绕行」。几条要点：
  - 来回两条的那一对状态做成一样宽（上下摆）或一样高（左右摆），并且对齐，两条线才都是直的；两条线之间要放得下夹在中间的那个标签，放不下就把这一对一起做宽，而不是只加宽一个。
  - 自环优先放在上边，标签落在圈外；放在下边时标签落在圈里面，圈要比标签宽。
  - 回头的线和自环不放在同一侧；放同一侧时，回头的线绕得比自环高出一行字。
- **连线上的标签**：写「事件 [条件] / 动作」，没有的部分省掉，比如「pay [card ok]」「cancel」「timeout / notify」。标签用英文短语，越短越好；超过三四个词就把条件或动作挪进图例，标签只留事件。
- **panel**：复合状态，也就是一个状态里还分子状态，画成一个带标题的浅色容器，标题是父状态名，子状态在容器里排成一行。从外面进来、往外面出去的转移连容器本身，不连里面的子状态；只有用户点名「从 Shipped 直接到 Delivered」才连子状态。只做一层嵌套，再深就拆成两张图。
- **legend**：用了虚线表示「系统自动触发」、或把条件挪进图例时，放一个三行以内的图例。

### 配色倾向

主路径上的状态用蓝色，成功结束的状态（已送达、已完成）用绿色，失败或取消的状态用红色；不在主路径上、也不算成功或失败的中间状态（等待客户、挂起、审核中）用黄色或橙色；复合状态的容器用浅紫，里面的子状态用紫色。初始点和终止双圈是墨色。连线保持默认墨色。

### 数量上的判断

- 一张图十个状态以内最好读；超过就把一组状态折成一个复合状态，或拆成两张。
- 一个状态出去的转移超过四五条时，图会变成一团线：看看是不是几条转移可以合成一条带条件的。

## 3. 出图

出图、命名、导出格式、两层质量关、迭代：调 skill `steps`（Claude Code 用 Skill 工具调 `excalidrawer:steps`；其他宿主读 `../steps/SKILL.md`），看它的『出图』。这一步只读这一节。状态机的文件名用 state-machine-<name>。

## 4. 常见画坏法

| 画坏了长什么样 | 为什么 | 回到哪一步改 |
|---|---|---|
| 转移的标签压住了两边的状态框，或贴上了箭头头 | 状态之间的间距按框排，或只按标签宽度留、没算箭头头 | 构图：stack，间距按标签加箭头头留 |
| 整排状态之间空得很开，线拉得很长 | 为一条特别长的标签把整排的间距都加大了 | 构图：stack，只撑开那一段，或缩短那条标签 |
| 来回两条转移叠成一条线，箭头头对在一起 | 两条都交给自动选边，落在了同一个中点 | 构图：连线，两条各钉在边的一侧 |
| 来回两条分开了，但夹在中间的标签贴着另一条线 | 两条线挨得太近 | 构图：连线，偏移拉开，还挤就把这一对框一起做宽 |
| 来回两条里有一条拐了一下，不是直线 | 这一对状态一宽一窄，同一个位置落在不同的地方 | 构图：连线，这一对状态做成一样宽并对齐 |
| 自环的圈很窄，箭头头和标签挤成一团，或标签压在圈的竖线上 | 出入点在边上靠得太近；圈在下边时标签落在圈里，圈比标签窄 | 构图：连线，自环放上边，或把圈拉得比标签宽 |
| 回头的转移从中间的状态里穿过去 | 回头的线没绕到整排外面，或绕得不够远 | 构图：连线，回头的线从主路径不用的边出，绕到整排上方或下方 |
| 自环的圈和回头的横线撞在一起 | 两者都在上方，离边一样高 | 构图：连线，回头的横线比自环高出一行字，或自环换到下边 |
| 主路径弯来弯去，看不出正常情况怎么走 | 没先挑主路径，按状态出现的顺序摆 | 构图：先挑出主路径排成一行，其余状态放下面 |
| 从外面进复合状态的线连到了某个子状态上 | 连了里面的卡片，没连容器 | 构图：panel，进出复合状态连容器本身 |
| 找不到从哪开始、在哪结束 | 少画了初始点或终止双圈 | 构图：形状，初始点指向初始状态，每个终止状态接一个双圈 |
| 出图后质量关有警告，或看图有一条不过 | 前面某一步的几何没改对 | 出图：按警告和自检的结论改，回到对应的构图那一项 |
