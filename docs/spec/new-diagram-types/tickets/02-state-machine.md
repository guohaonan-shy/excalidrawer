# 02 — 状态机入口 skill

**Blocked by**：01 — 登记三个新入口 skill 的名字
**设计冻结**：不涉及 UI

## 要建什么

用户说「画个订单状态机」，有一个 `state-machine` 入口 skill 接住：问清状态和转移，画出第一稿就能用的状态机。按步骤 skill「新增一种图类型」一节的清单写（入口 skill 只有一个自然语言的 SKILL.md，四步：问清楚 → 构图 → 出图 → 常见画坏法；不许写坐标、尺寸、工具名、sugar 字段、代码块）。

图的形态（总 spec「方案 → 状态机」）：

- 状态是圆角框，转移是带箭头的线，线上写「事件 [条件] / 动作」，没有的部分省掉。
- 主路径（从初始到终止最常走的那条）排成一行，其余状态另起一排放在下面。回到前面状态的转移从主线不用的边走；同一对状态之间来回两条转移各占一条边的两侧，不叠在一起；自环在状态框的一条空边上绕个小圈回来。
- 初始：一个实心小圆点加一条箭头指向初始状态。终止：双圈（外圈空心、内圈实心）；用户没提终止就不画。
- 复合状态只做一层嵌套：子状态放进一个 panel，panel 标题是父状态名。
- 澄清问题：内容（有哪些状态、哪些转移和它们的事件 / 条件）用户说全了就不问；主路径横排还是竖排是「怎么画」的选择，用户没说就问（状态名长、数量多时推荐竖排）。

几何全用现有组件，不加新组件：主路径用 stack 排，转移是连线，复合状态是 panel。连线的参考里现在有回边、出入边、标签避让、长距离绕行，缺两种写法，这张工单补上：

- **自环**：从状态框同一条边上的两个点出入，U 形绕出去再回来（复现过：用边上的点加 U 形绕行就能画，Layer A 零警告）。
- **双向转移**：同一对状态之间方向相反的两条，用固定出入边加各自的偏移分开，两条的标签不叠。

还要交付一张真实示例：一个新的状态机 figures 模块，README 图库脚本只加它的导入和一次调用，README *What it makes* 加一格，`docs/gallery/` 加一张 PNG。

## 验收标准

- [x] 新入口 skill 通过入口 skill 约定测试（目录一建就被自动覆盖）
- [x] 入口 skill 的四步写全：问清楚（内容可跳、方向要问）、构图（形态、用到的组件、配色倾向）、出图（调步骤 skill「出图」）、常见画坏法
- [x] 连线参考新增「自环」「双向转移」两节，每节写清什么时候用、怎么画、画坏了什么样
- [x] 示例状态机至少含：初始点、终止双圈、一条回边、一个自环、一对双向转移、一个一层的复合状态；Layer A 零警告
- [x] 图库脚本连跑两次 PNG 字节一致；重跑后别的图的 PNG 没变
- [x] 照一个真实请求用新入口 skill 画一张，Layer A、Layer B 都过，PR 里附图
- [x] CHANGELOG 只在 Unreleased 下记一条

## 选中的存量回归

- `tests/skills-entry.test.mjs`：新入口 skill 正文的约定。
- `tests/skills-steps.test.mjs`：连线参考变长；它核步骤 skill 的行号表和参考文件。
- `tests/linear.test.mjs`、`tests/validate.test.mjs`：自环和双向转移依赖连线的固定出入边、偏移和 U 形绕行，以及连线穿框的检查。
