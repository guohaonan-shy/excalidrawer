# 03 — 金字塔 / 漏斗：taper 组件、填色多边形、pyramid 入口 skill

**Blocked by**：01 — 登记三个新入口 skill 的名字
**设计冻结**：不涉及 UI

## 要建什么

用户说「画个需求层次金字塔」或「画个注册转化漏斗」，都由一个 `pyramid` 入口 skill 接住，画出逐层收窄、填了色的梯形。现在画不出来：梯形只能用原始线条元素拼，导出的 SVG / PNG 丢了填充（只剩轮廓），而且每层斜边的坐标、每层能放字的宽度都得 agent 手算。

三样东西：

1. **填色多边形形状**：sugar 加一种多边形形状，给一串顶点和填充色，导出成闭合、填色的多边形；在 Excalidraw 里打开是一个闭合的线条元素。Layer A 把它当成跟矩形同等的形状：参与重叠、连线穿框、文字与底色对比度的检查，范围取顶点的外接矩形。只为梯形加，不做通用的多边形绘图能力。
2. **`taper` 组件**：给层的列表（每层的文字，漏斗再带一个数）、朝向（上窄 = 金字塔，下窄 = 漏斗）、最宽一层的宽度，返回每层梯形的四个角、层名能用的文字框（按这一层最窄的那条边算，放不下就折行、这一层跟着长高）、右侧数值的锚点、相邻两层之间转化率的锚点。层宽按层序等步收窄，不按数值缩放。只返回坐标，跟 stack / panel / axis / legend 一样从库入口导出、经 `compute_layout`（MCP 与 CLI 共用的工具定义）和 CLI 可调；参数类型错一律抛错，写明组件名与参数。步骤 skill 加一份 `taper` 的参考，「组件」表加一行指向它（行号表跟着改）；形状与文字的参考里加多边形。
3. **`pyramid` 入口 skill**：按步骤 skill「新增一种图类型」的清单写。构图分金字塔、漏斗两节：每层一个梯形，层间留缝、左右对称；层名压在梯形中间；数值写在层的右侧，漏斗再在相邻两层之间写转化率。澄清问题：内容（每层是什么、漏斗每层的数）说全了不问；金字塔还是漏斗按有没有逐层递减的数判，都不像才问；漏斗显示绝对数、转化率还是都显示，用户没说就问。

和别的工单共享的文件、怎么避免冲突：布局模块和 `compute_layout` 的工具定义里，这张工单只在末尾加新组件、在派发表和说明末尾加新项（工单 04 同时在改 axis 那一处，不要碰）；sugar 模块可能跟 #38 小修（中文箭头标签估宽）同时在改，后合的一方先合最新的 `release/0.6.0`。

示例：一个新的 pyramid figures 模块出金字塔、漏斗各一张，README 图库脚本只加它的导入和一次调用，README *What it makes* 加两格。

> 人的决定（2026-10-28，review 第 1 轮 S2）：「S2 接受」——多边形构造函数跟矩形、箭头、线条等基本图元一样从库入口导出；「只为梯形加」指不为它做通用多边形的组件和 skill 指导，不限制库入口导出。

## 验收标准

- [x] 含多边形的 sugar 展开后导出的 SVG 里是填了指定颜色的闭合多边形
- [x] 多边形与一个矩形重叠时 Layer A 报重叠；多边形上的深色字在浅底上不报对比度
- [x] `taper` 对 4 层漏斗（1000 / 400 / 120 / 30）：层自上而下逐层收窄、互不重叠、左右对称；每层文字框落在梯形内；最后一层放得下约 12 个字符的层名（折行后层长高）
- [x] `taper` 参数类型错时抛错，错误信息带组件名和参数名
- [x] `compute_layout` 能调 `taper`，结果与直接调用相同；步骤 skill 的约定测试确认它已写进参考
- [x] `pyramid` 入口 skill 通过入口 skill 约定测试
- [x] 两张示例 Layer A 零警告；图库脚本连跑两次 PNG 字节一致；重跑后别的图的 PNG 没变
- [x] 照一个真实请求用新入口 skill 画一张，Layer A、Layer B 都过，PR 里附图
- [x] CHANGELOG 只在 Unreleased 下记一条
- [x] 不改 #12 的 issue 状态
- [x] review 第 1 轮 S1（2026-10-28）：`taper` 对每一对相邻层都返回层间转化率的锚点，不论每层有没有给数、给的是不是数字；比例和百分比文字只在两层都是数字且上一层大于 0 时才带上。用户只给层间转化率（每层没有数，或数写成「10,000」这类带格式的文字）时，4 层漏斗也返回 3 个层间锚点；taper 参考和 pyramid 入口 skill 里「只显示转化率」那条路的说明与此一致
